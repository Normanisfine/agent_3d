\section{Token accounting for the agent supervisor}
\label{app:tokens}

The runtime ledger records worker calls but not the supervising agent, which in AHA-driven-short accounted for 93.5\% of input tokens (26.0M of 27.8M). We therefore read the supervisor's own session log, which records the token usage of each model call, and grouped calls by the action that preceded them. A call that followed a \texttt{sleep} or an empty poll of a running command is counted as waiting. The grouping is heuristic; token counts are as recorded.

The 149 waiting calls processed 18.4M cached and 53k uncached input tokens and produced 16k output tokens, an estimated \$19.78 of the supervisor's \$28.88. The supervisor slept for 1,265\,s in total. Its context grew from 21k to 172k tokens; printing session files and viewing 50 images contributed about 40\% of the growth.

Moving from short to long waits removed \$16.76 of cached input, the cost of re-reading history, while the other two columns barely changed. AHA-auto spends little on cached input; most of its cost is fresh worker input, which points to smaller worker requests as the next saving.
