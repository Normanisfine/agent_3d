## 1. Cover (0:20)

> Hi Sashank. We're 3Heads1GPU. Our project asks one question: when an LLM agent rebuilds a room from a phone video as an editable Blender scene, where do the small objects go?
>
> The two rooms on the right were rebuilt from video by the pipeline we study. One is from our dev set and one from our test set.

## 2. The problem (0:45)

> We ran the baseline on four rooms and scored every ground-truth object, split by size.
>
> It places about a quarter of the medium and large furniture correctly, and almost none of the small things. Zero of 162 extra-small objects, like mugs, remotes and plates, are right. Only 3 of 212 small objects, like lamps and cushions, are right.
>
> These two bins make up 64 percent of all objects in the ten test rooms we are running. So we want to know how much is lost, at which stage, and which fix is worth its cost.

## 3. The baseline pipeline (1:40)

> The pipeline has two layers.
>
> The top layer is **reference geometry**. It is computed once per video and uses no LLM.
>
> 1. The input is one continuous phone shot, and 32 frames are sampled evenly.
> 2. Pi3X estimates the camera poses, intrinsics, depth and a point cloud.
> 3. SAM 3 masks the structure in every frame (walls, floor, glass, mirrors) from text prompts.
> 4. RANSAC fits the floor and walls, which fixes gravity. A TSDF fusion at 3 cm then gives a reference model of the whole room.
>
> The bottom layer is the **agent loop**: an LLM writes Blender code and then checks it.
>
> 5. **Measure.** The agent picks landmark pixels in the frames, and a tool returns 3D lengths and heights from the point cloud.
> 6. **Build.** It writes Blender Python: boxes, cabinets with working doors and drawers, and assets from a library.
> 7. **Verify.** It renders the scene from the source cameras and draws per-object X-ray outlines on the frames. It also checks mask fit, collisions, support and a drop test.
> 8. **Review.** A separate, read-only vision-language model checks every object. It either accepts, or rejects with findings, and then the agent repairs and re-renders.
>
> The output is an editable .blend file in which every object is a named part. We only ask for geometry, a grey whitebox, because geometry is what we score.

## 4. Five arms (1:00)

> We test five arms, and each adds one thing to the one before it.
>
> - **A0** is the released prompt, unmodified.
> - **A1** only changes the prompt: build every visible small object, with code only. This is our fair baseline.
> - **A2** adds a detector inventory, meaning 3D boxes and crops from the full-resolution frames.
> - **A3r** adds image-to-3D generation for items under half a metre. Our tool, place_mesh, fits each generated mesh into its box and keeps it only if it beats a plain box.
> - **A3v** has the same tools, but the agent decides what to generate.
>
> Everything else is held fixed: perception is computed once per room, the agent is the same model at the same effort level, there are no time or turn caps, and arms can't see each other's files.

## 5. Test results (1:15)

> These are the test results so far: three rooms, all five arms, 513 objects. "Placed right" means the center is within half the true box's half-diagonal, or within 10 cm, and the size ratio is between 0.67 and 1.5. We froze this rule before we scored any test run.
>
> Every arm beats the baseline. Going from the baseline to A2, small objects rise from 1 to 17 percent and medium from 24 to 38, with no loss on large objects.
>
> But extra-small objects are still 86 to 93 percent missed in every arm. One caveat: 116 of the 138 extra-small objects are in one room. Averaged per room instead, extra-small goes from 0 to 0.14 with A1 and 0.17 with A2.
>
> Cost is flat across arms: about an hour and 9 to 14 dollars per room at API list prices.

## 6. Three findings (1:15)

> Here is where the small objects go. We have one finding per stage.
>
> **Find.** In a dev room the detector's inventory contains only 2 of 24 extra-small objects, while the agent alone built 18. Across five dev rooms, 99 percent of these objects are visible, but the detector finds only 16 percent.
>
> **Shape and place.** Six generation runs produced 160 meshes, and only 5 ended up in a final scene. Hunyuan3D-2mini mostly returns flat slabs, and our placement gate rejects them. We calibrated that gate on dev and then froze it, so we report this failure rather than loosening the gate.
>
> **Check.** The reviewer accepted only 3 of 15 test runs, and two of those are baseline runs that placed no extra-small object right.
>
> So the agent finds small objects better than the detector does. What fails is placing them, and a whole-room review doesn't notice.

## If asked

- **How exactly do you score?**
  - Ground truth is CA-1M's exhaustive 3D boxes, about 125 per video.
  - We align with Sim(3) on the camera trajectory, never on the scored objects.
  - Matching is greedy and class-agnostic.
  - Every object ends up placed right, built but wrong (within 30 cm), or missed.
- **Why size-normalized distance and not IoU?**
  - For a 10 cm object, a few centimetres of camera error already pushes IoU to zero.
  - We still report IoU ≥ 0.25 alongside, and under it every arm still beats the baseline in every bin.
- **What does place_mesh do?**
  - A coarse search over 5 up-axes and 36 headings, then gravity-constrained ICP, then silhouette refinement against the masks.
  - On synthetic objects it recovers pose within 2 cm and 5 degrees.
- **Isn't Boxer trained on CA-1M?**
  - Yes, so it is same-source, and we flag it in every table.
  - The clean SAM 3 control isn't trained on CA-1M. It finds somewhat more extra-small objects (27% vs 16%), and our no-LLM pipeline places about equally well with either inventory.
- **Why is L recall low even for the baseline?**
  - We haven't broken L down yet. Our guess is that large items such as counters and wardrobes are built merged or approximate, and then fail the size test.
  - Our small-object arms don't make L worse.
- **One run per arm?**
  - Yes, for now. A second seed for A1 and A3v estimates the noise, and we won't claim differences smaller than that.
- **Did you tune anything on the test set?**
  - No. The scoring rule and the placement gate were frozen on dev before we scored any test run.
- **Who made the material renders?**
  - The same agent, in a separate appearance pass on a finished run.
  - They're for presentation only. Scores use the grey geometry.
