# SceneRig 读码结论（10-29）

论文主页 https://red-fairy.github.io/SceneRig/ ，代码 https://github.com/Red-Fairy/SceneRig （MIT 协议，读的是 commit `2defb4b`，10-02）。作者来自 Luma AI 和 Cornell，论文还没挂出来。只读了代码，没有运行。

## 它做什么

输入一张照片，可以另给度量深度和内参。输出是一个 Blender 场景，每个物体是单独的网格，带材质和灯光，经过重力沉降后导出 USD 给 Isaac Sim 用。agent 默认用 Claude。用到的模型：

| 用途 | 模型 |
|---|---|
| 度量深度 | MoGE-2 |
| 列物体清单 | 视觉语言模型 |
| 分割 | SAM 3 |
| 用"指点"确认物体实例 | MolmoPoint-8B |
| 单物体生成 3D | SAM 3D Objects |
| 补全被遮挡的物体 | Qwen-Image-Edit（LanPaint） |
| 新视角 | SHARP，可选再用 gpt-image 修图 |
| 物理 | Isaac Sim 5.1 |

一共要 7 个互相独立的环境，约 150 GB。

## 和我们的问题对得上的四处

1. **小物体检测：放大再检测**（`lib/tools/geometry/agentic_mask.py`，`tiered` 那段）。
   - 先由视觉语言模型列出物体，每个实例配一句描述，再由 MolmoPoint 在图上点出它的位置。
   - 第 1 层：SAM 3 在整张图上按类别分割，取包含那个点的掩码。
   - 第 2 层："全图检测漏掉的小物体"，以那个点为中心裁出 1/3 × 1/3 的窗口，放大后再跑一遍 SAM 3，结果映射回全图。
   - 第 3 层：用所有的点去提示 SAM 3 的交互分割，作为最后的退路。
   - 两个模型都认可的才算一个物体。
   - **对我们：** 我们的清单在整张高清帧上检测。开发集 XS 物体在高清帧里 99% 看得见，但只检测到 16%（Boxer）和 27%（SAM 3 干净对照）。瓶颈在检测器，不在相机。放大再检测正好对着这一步。
2. **生成：输入整张图，不是小裁图**（`lib/tools/sam3d/sam3d_worker.py`、`generative_resegment.py`、`mesh_place.py`）。
   - SAM 3D 的输入是整张图、物体掩码，再加 MoGE 点图，模型能看到物体周围的场景。
   - 被遮挡的物体先由视觉语言模型判断"谁挡了谁"、关键部件（桌腿、显示器支架）有没有被挡住，再用图像编辑补全，补全后重新分割，然后才生成 3D。
   - 放置时保留 SAM 3D 给的形状和朝向，等比缩放到 MoGE 框的对角线长度，中心放到 MoGE 给的位置。
   - **对我们：** A3 用 Hunyuan3D-2mini，只喂物体的小裁图，所以多半生成扁片：测试集 160 个生成里，摆放工具只接受了 10 个。换 SAM 3D，并且给它整张图和掩码，是最直接的改法。
3. **位姿：渲染后打分**（`register_objective.py`）。
   - 打分 = 剪影 IoU + DINO 外观相似度 − 深度偏离 MoGE 的比例 − 面积比偏差。
   - 深度项用来打破"从单一视角看，深度和尺度可以互相抵消"的歧义。
   - **对我们：** `place_mesh` 只比剪影和点，没有深度项。小物体的尺度和深度最容易互相抵消，可以加一项。
4. **支撑关系和沉降**（`scene_graph.py`、`settle_geometry.py`、`isaac/`、`same_size.py`）。
   - 视觉语言模型先提出"谁放在谁上面"，再用平面拟合和物体底面足迹做几何校验，两者不一致时由模型裁决。
   - 物体按支撑顺序依次放下，穿模时往上抬到不穿为止，最后在 Isaac 里沉降。
   - `same_size.py` 让同类物体共用一个尺寸，比如一摞盘子、一排杯子。
   - **对我们：** "建了没摆准"在 S 档比"建对"还多（Opus A1 测试集 .20 对 .14）。对小物体做"贴到支撑面再沉降"，正对这个问题。同尺寸约束也适合柴堆、杯子这类重复物体。

## 不能照搬的地方

- **场景范围不同。** 它是单张图里的一个工作台，提示词里写明要忽略"地上散落的小东西（包、盒子、鞋、线缆、杂物）、人手里的东西、第二张桌子和上面的东西、远处的面"。我们是整段视频里的整个房间，42898849 一个场景就有 116 个 XS。
- **数字不能直接比。** 它报告的位置误差 2.4 cm（OSPA@5）是桌面场景上的，机器人实验还用了实测深度。
- **太重，不能整套搬过来。** 只能挑部件用。

## 对我们计划的影响

- **SAM 3D 在 Blackwell 显卡上跑不了官方环境。** SceneRig 的安装脚本（`scripts/install.sh`）写明："SAM 3D pins torch 2.5.1+cu121, which has no kernels for compute capability 10.x/12.x"，检测到 Blackwell 就跳过 SAM 3D。
  - Betty 是 B200，计算能力 10.0；集群只支持 CUDA 12.8。我们笔记本的 RTX 5070 Ti 计算能力是 12.0。
  - 我们的 `scripts/betty/sam3d.sbatch` 用的正是官方环境，大概率跑不起来。
  - 可选的路：
    1. 在没有 Blackwell 的显卡上跑。Colab A100 有 40/80 GB，SAM 3D 官方要 32 GB。
    2. 把 SAM 3D 的依赖移植到 torch 2.7+cu128 再重新编译，工作量不确定。
    3. 换一个支持新显卡的图生 3D 模型。SceneRig 代码里提到 TRELLIS.2 也是一个选项。
  - 11/2 定训练加分项去留之前，要先选定其中一条路。
- **可以借的、成本最低的两件：**
  - 放大再检测：只改清单这一步，在开发集上只看"检测到"这一个数，不用跑 agent，也不花 Claude 额度。
  - 贴到支撑面再沉降：可以做成后处理。
- **规矩照旧：** 这两件都只能在开发集上做好，再作为新的实验组拿到测试集上跑一次，不能回头改已有各组的结果。
