9算力、驱动和花费

这个项目有三个钱袋子，用途分得很死。

  • 两份订阅。Yifan 的 ChatGPT 订阅和 Claude Max，各每月 100 美元。只能用来驱动 agent。
  • Betty 课程额度。每人约 50 美元，三人约 150 美元。跑感知和正式的 SAM 3D 生成。
  • 自掏腰包。最多 10 美元，只用于 fal 上的 SAM 3D 核对。

没有额外的 API 预算。所以成本没法直接看账单，要自己记 token 再折算（9.4 节）。

大白话

订阅像健身房年卡：不按次收费，但有“每段时间最多来几次”的隐形上限，次数用完就得等。Betty 像按小时计费的共享厨房，课程替我们付了一笔押金。fal 像外卖，单价便宜，但我们只点 10 美元的，用来尝尝味道对不对。

9.1 什么跑在哪

分工的原则：要看图、要渲染的 agent 循环留在笔记本上；吃显存的模型放 Betty；订阅只管“大脑”。

四个地方，箭头上是传的东西
  1. 笔记本（RTX 5070 Ti 12 GB，Ubuntu 24.04）。跑 agent 的命令行工具、Blender 5.2.1、开发期的 Hunyuan3D-2mini、place_mesh 和评测脚本。默认分辨率的 Pi3X 和 SAM 3D 都跑不动。
  2. 订阅。ChatGPT 订阅登录 Codex CLI，驱动 GPT-6 跑主实验；Claude Max 登录 headless Claude Code，驱动 Opus 5.5 做开发和 5 个场景的复跑。
  3. Betty 跑感知。GPU 是 B200（每卡 180 GB），另有 90 GB 和 45 GB 两种 MIG 切片。Pi3X、SAM 3、Boxer、干净对照都在这里按场景算一次，结果拷回笔记本。走 SSH 加 Slurm，要连 Penn 的 VPN。
  4. Betty 跑生成。正式实验的 SAM 3D 部署在 mig45 切片上（约 22 GB）。gen3d_request 从笔记本提交请求，网格拷回来给 place_mesh。
  5. fal（托管 API）。SAM 3D 一次 0.02 美元，10 美元约 500 次。只用来在 Betty 装通之前，拿几个已知物体核对 SAM 3D 返回的位姿是什么坐标约定。
算例 · Betty 额度够跑多少

PARCC 的 FY27 价格表：整卡 B200 补贴价 1.00 美元/小时、非补贴价 4.51；mig45 补贴价 0.25、非补贴价 1.13。

  • 每人 50 美元，按补贴价：mig45 能跑 50 / 0.25 = 200 小时，整卡 50 小时。
  • 按非补贴价：mig45 约 50 / 1.13 ≈ 44 小时，整卡约 11 小时。
  • 感知（估算，调研笔记 04 的假设）：每个场景约 0.5 GPU·小时，20 个场景约 10 小时。mig45 上补贴价 2.5 美元，非补贴价约 11.3 美元。

课程的 50 美元按哪档价格扣，公开文档没写，要问课程。不管哪档，只跑感知都很宽裕；剩下的给 SAM 3D 和可能的训练加分项。

容易搞错
  • Blender 不上 Betty。NVIDIA 的 MIG 文档写明切片不支持任何图形接口（OpenGL、Vulkan），而 AHa-3D 的预览渲染用 Workbench 和 EEVEE，都要图形上下文。整卡能不能用没核实。
  • 计算节点能不能上网没写清。文档只有一句 egress restricted。所以权重先在登录节点或一个短的 CPU 作业里下好，GPU 作业离线跑。
  • 登录节点不许跑重活。规矩是 edit, sync, submit, not train，算东西要走 srun 或 sbatch。

设计文档第 3、6、7、13 节；调研笔记 04 第 1.1–1.8、1.10 节（PARCC 系统页、费率页、Slurm 页、NVIDIA MIG 文档）。

9.2 驱动模型怎么选，为什么全程不换

驱动模型就是扮演 agent 的那个大模型。AHa-3D 的 harness（工具和流程）不变，换的只是“谁在想”。

为什么主实验用 GPT-6。Codex 是 AHa-3D 原生的驱动方式，作者博客用的就是 GPT-6 Astra（推理强度 medium）。这样最接近复现作者的设置。

为什么还要 Claude。开发调试用得多，Claude Max 的额度可以分担；5 个场景的复跑回答“换一家模型，结论还成立吗”。

AHa-3D 的 README 说 Opus 5.5 初步实验能驱动，但没充分测过，原文是 Opus 5.5 can also drive this repository based on initial experiments, but it has not been fully tested。

公开证据能参考的是 Agentic RSR（arXiv 2610.10479），它在 18 个 Blender 场景上比过一批模型。

为什么全程不换驱动
  • 组间比较要求同一个驱动。A1 和 A3v 之间的差，必须只来自“加没加生成”，不能混进“换了个模型”。
  • 削减顺序里没有“换驱动”这一项。额度不够时砍场景、砍组、砍重复，驱动不换。换驱动会破坏“复现作者设置”这个前提。
  • 推理强度也固定。设计文档要求所有组同一个推理强度，具体档位没写死；作者博客用的是 medium。
  • Claude 复跑是另一张表。它和主实验分开报，不混进同一个比较。
容易搞错
  • 便宜模型在长任务上可能撑不住。Haiku 5.5 跑 office48 只用了 5.7 分钟、67 轮，结果粗糙，验收在第一关没过；它在 BVB 榜上分数却不差。BVB 是几分钟的短任务，榜单分数不能直接搬。
  • 不要引错表号。“Astra 18/18 对 GPT-5.6 Sol 10/18”是 v1 的表 4；v2 把它挪到了附录表 9（Codex harness），新加的表 3 换成了 DSH harness。

9.3 第 1 周先量额度

订阅不按次收费，但有用量上限。一次 AHa-3D 运行吃掉多少额度，没人知道。所以第 1 周（10 月 14 日到 19 日）先在 office48 上用两个驱动各跑一次，量出来再定能跑多少次。

量额度：跑两次 → 记五样 → 定计划和上限
  1. 跑两次。office48 就是作者博客里的那间办公室，有现成的 token 账单可以对照。两个驱动各跑一次，都用正式实验的设置。
  2. 记五样。token 分输入、缓存、输出三类记；墙钟时间和轮数；这一次占当期订阅额度的比例；按官方 API 价折成的美元；顺便粗看场景质量，确认没跑崩。
  3. 定计划。额度够就按原计划跑（Claude 复跑 5 组 × 5 场景 = 25 次）；不够就按削减顺序砍（9.4 节），驱动不换。同时定下墙钟和轮数上限：初值是 A1 在开发集上的中位数乘 2。

算法 · 一个订阅周期能跑几次

设一次 office48 运行占当期额度的比例是 q，一个 CA-1M 场景比 office48 多花的倍数是 k，那么一个周期最多约 ⌊1 / (q × k)⌋ 次。

  • q 由第 1 周实测。
  • k 按我们的理解大于 1：office48 是 10 秒的片段，CA-1M 每个视频约 125 个真值物体，认真建小物体的组会多转很多圈。k 要在开发集的前几个场景上量。
  • 把 11 月 9 日前剩下的周期数乘上去，就是主实验能用的总次数，和 9.4 节的计划次数比。

9.4 成本口径和运行次数

结论要画成“成本对精度”的曲线，成本轴就得有一个统一口径。设计文档定的是 API 等价美元。

API 等价美元 = Σ（各类 token 数 × 该模型的官方 API 单价）+ fal 生成费

订阅按月付费，这个数并不是我们真花出去的钱。它只用来在各组之间、各模型之间做同一把尺子的比较。

GPT-6.1 Sol20.1010订阅里没有 Astra 时用它

算例 · 作者那次 office48 按这个口径折多少
  • 缓存输入 9,551,232 × 1 / 10⁶ = 9.55 美元。
  • 剩下 252,335 token 分不清输入输出：全按输入 2.52 美元，全按输出 12.62 美元。
  • 合计 12.07 到 22.17 美元。这就是 2.4 节那个“12 到 22 美元”的来历。
  • 同样的 token 量按 Opus 5.5 的价：缓存 9,551,232 × 0.20 / 10⁶ = 1.91，剩下的 1.01 到 5.05，合计 2.92 到 6.96 美元。

所以每次运行都必须把三类 token 分开记，不然算出来就是一个很宽的区间。

计划的运行次数如下。P0 不调大模型，几乎不花额度，不算在内。

额度不够时的削减顺序（设计文档第 5 节）
  1. A0 缩到 5 个场景。
  2. Claude 复跑只保留 A1 和 A3v。
  3. 第二次重复缩到 3 个场景。
  4. 取消 A4。
  5. 测试场景从 15 个减到 10 个，驱动不换。按物体配对比较，10 个场景仍有上千个真值物体。
  6. 去掉 A3r，只留 A3v。P0 已经代表了“按规则、不用大模型”这一端。

第 5、6 步是推荐写进去的，用户还没有明确确认。

容易搞错
  • Betty 和 fal 的钱另算。API 等价美元只管 agent 的 token；fal 的生成费另外加进成本轴；Betty 的 GPU 小时单独记，不混进同一个数。
  • 失败的运行也有成本。撞上限、跑崩、重跑的 token 都要记，各组失败率单独报。

设计文档第 5、7、9.6、9.7 节；deep-aha3d.json 的 cost_compute（office48 token 数）。

9.5 硬盘和存储

笔记本硬盘只剩约 65 GB，这条约束直接决定了“什么数据不下”。

  • 不下原始 .mov。ARKitScenes 的原始视频每个约 0.9 GB，22 个约 20 GB。我们用 CA-1M 的帧按 10 fps 合成 mp4，就不需要它。
  • 大文件放 Betty。模型权重和中间结果都放 Betty；笔记本只放评测数据和最终的 .blend。
  • inode 可能比容量先用完。inode 是“文件个数”的配额，Betty 的 home 是 50 GB、25 万个。AHa-3D 每次运行会生成大量帧和中间文件，所以作业时写到节点本地的 /tmp/$USER，结束后打成 tar 包拷回。
  • 节点本地盘要自己清。/tmp/$USER 约 500 GB，同一节点上的人共用，用完要拷走并删除。
容易搞错
  • bundle 还是要拷回笔记本。agent 的测量和叠图工具在笔记本上读 bundle/。单个 bundle 多大，第一个场景跑完就量，再看 20 个场景放不放得下（设计文档没算这一笔，按我们的理解要预留）。
  • ScanNet++ 不是一定会下。要教授手签，11 月 2 日前批下来才加 5 个场景做形状指标。
必记结论
  • 订阅只驱动 agent；3D 模型在 Betty 和笔记本上跑；fal 只花 10 美元做核对。
  • 主实验 Codex 加 GPT-6，Claude 加 Opus 5.5 做开发和复跑，全程不换驱动。
  • 第 1 周先量额度，再定墙钟和轮数上限。
  • 成本轴是 API 等价美元，每次运行都要分三类记 token。
  • 计划 105 到 120 次 agent 运行；额度不够按削减顺序砍。

设计文档第 3、8、13 节（硬盘、数据量）；调研笔记 04 第 1.5 节（PARCC 存储页）。
