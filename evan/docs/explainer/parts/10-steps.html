10一步一步做

整个项目拆成 11 步，编号 S1 到 S11。每一步写清负责人、时间、要做的事和"做完的标志"，达到标志再往下走。

同一周里不同人的步骤可以并行。真正要排队的只有几处，先看依赖图，再看每一步的卡片。

10.1 依赖图：哪一步要等哪一步

大白话

像装修一个房子。水电（S1 环境）、量尺寸（S3 数据）、买材料（S4 感知）可以同时开工；贴瓷砖（S9 主实验）得等前面几样都到位才能动。

图里每个方块是一步，箭头上写的是交过去的东西。泳道按人分，跨三条泳道的长方块是三个人一起做的步骤。

S1–S11 依赖图：三条泳道，箭头上是交接的文件
  1. 第一周五件事并行（10/14–10/19）。Yifan 搭环境（S1），装好后量额度（S2）；Yujing 备数据（S3），有了真值框就写评测脚本（S5）；Mingjian 拿到 Yujing 的帧和 mp4 就在 Betty 上跑感知（S4）。
  2. 10/20 前定死（S6）。测试集名单和各项阈值写进两个配置文件提交，之后不改。它要等 S3 的视频名单和 S5 的评测脚本。
  3. 基线跑通（S7）。A0、A1 在 3 个开发场景上无人值守跑完。它要等三样东西：S1 装好的 AHa-3D，S4 算好的感知结果 bundle/，以及 S5 的评测脚本和 S6 定死的两个配置（绿线，打分要用）。10/26 中期检查交这一步的数字。
  4. 生成工具（S8）。Mingjian 用 S4 的掩码、点图和清单写通两个生成工具，部署 SAM 3D。11/2 是它的闸门，过不了就换方案（第 13 章）。

  6. 补充实验和报告（S10、S11）。主实验跑完才做补充实验，两者的结果一起进报告。

  • 图上的列只表示大致先后。S8 从 10/20 做到 11/02，和 S7、S9 都有重叠，准确日期以第 12 章的甘特图为准。

10.2 今天就要发出去的申请

有五样东西要等别人批或开通。它们不花多少力气，但等待时间不归我们控制，所以第一天就发。

大白话

就像装修前去物业办开工证。填表五分钟，批下来可能要一周；不先去办，师傅到了也进不了门。

  • SAM 3 和 SAM 3D Objects：Hugging Face 上两个模型都是人工审批（gated: manual）。没有 SAM 3，AHa-3D 的 Observe 一步就跑不起来，S1、S4、S7 全卡住，干净对照的掩码也没了；没有 SAM 3D，正式实验的生成器就没了。
  • 先查 SAM 3 的权限：Yifan 之前在这台笔记本上跑过 AHa-3D 的 SAM 3，他的 HF 账号可能已经有权限。先查一下，没有再申请。
  • ScanNet++：申请表要教授手签。批下来才加 5 个场景的形状指标，11/2 前没批就不做。
  • Betty：导师（PI）在 ColdFront 里把人加进项目，新账号最多一小时生效。登录要在 Penn 校园网或 GlobalProtect VPN 上，认证三选二（Kerberos、SSH key、Duo）。
  • fal：自费上限 10 美元，由谁出还没定。只用来核对 SAM 3D 的位姿坐标约定。按每次 0.02 美元算，10 美元约 500 次，核 5 个物体绰绰有余。
算例 · fal 的 10 美元够用几次

fal 上 SAM 3D Objects 标价每次 0.02 美元（02 号笔记）。10 ÷ 0.02 = 500 次。核对位姿约定只需要 5 个物体，就算每个物体试 10 种设置也只用 50 次，即 1 美元。

设计文档第 3、6、8 节；04 号笔记 §1.2（Betty 账号和认证）；03 号笔记 §0（ScanNet++ 审批约 4–7 天，来自 issue 里的用户反馈）；02 号笔记（fal 价格）。

10.3 S1、S2：搭环境和量额度（Yifan）

第一周 Yifan 要在笔记本上把 AHa-3D 原样跑通，并量出"跑一次花掉多少订阅额度"。后面所有实验的规模都由这个数决定。

笔记本上装什么，额度怎么量
  1. Blender 和 AHa-3D。Blender 必须是 5.2.1，AHa-3D 只能在 Linux 上跑。仓库固定在提交 82f4b11（或我们 fork 后的固定提交），所有实验组用同一个版本。
  2. 三个 Python 环境。按 AHa-3D 的安装文档，Pi3X、SAM 3、Open3D 各一个环境，互不干扰。本地只用它们跑通流程，正式的感知结果在 Betty 上算（S4）。
  3. 两种驱动。Codex CLI 用 ChatGPT 订阅登录驱动 GPT-6，这是主实验的驱动。Claude Code 的无头模式（claude -p）用 Max 订阅驱动 Opus 5.5，用于开发调试和复跑。AHa-3D 的审查步骤写死了 codex exec --image，在 Claude 那边要用转发 shim 把这条命令接过去。
  4. 量额度。office48 用两个驱动各跑一次，记 token 数、耗时、占当期额度的比例，汇成一张额度表。确认订阅里有没有 GPT-6 Astra，没有就用 Sol。
S1 · 搭好本地环境

负责 Yifan 10/14–10/19

  • 克隆 AHa-3D，固定提交号；装 Blender 5.2.1。
  • 按安装文档建 Pi3X、SAM 3、Open3D 三个环境。
  • Codex CLI 用 ChatGPT 账号登录；准备 Claude Code 的无头模式和转发审查的 shim（之前的会话里做过）。

做完的标志：作者的 office48 示例能无人值守地从头跑到出 .blend。

S2 · 量额度

负责 Yifan 10/14–10/19

  • office48 用 Codex + GPT-6 跑一次，用 Claude Code + Opus 5.5 跑一次。
  • 记录 token 数（输入、缓存、输出）、耗时、占当期订阅额度的比例。
  • 据此定每次运行的墙钟上限和轮数上限，所有组共用。初值取 A1 在开发集上中位数的 2 倍，等 S7 有了 A1 的数再定。

做完的标志：一张额度表，写清一次运行用掉多少额度。据此确定第 4 章的运行次数，以及第 13 章的削减顺序要不要提前启动。

容易搞错

订阅不按次计费，额度表里的"花费"是 token 数按官方 API 价格换算出的"API 等价美元"。这是折算出来的成本单位，用来在各组之间比较。

10.4 S3：准备数据（Yujing）

S3 把 CA-1M 的原始数据拆成两路：一路变成 AHa-3D 能吃的输入视频，一路变成只给评测用的真值。两路之间不许串。

S3 · 准备数据

负责 Yujing 10/14–10/19

  • 下载 CA-1M 验证集里和 BVB-150 重叠的 22 个视频（约 11 到 16 GB），以及 VSI-Bench 的 ScanNet++ 部分（视频约 1 GB）和元数据。
  • 把 CA-1M 的帧按 10 fps 合成 mp4。不下 ARKitScenes 原始的 .mov，硬盘放不下。
  • 读出每个视频的真值框，去掉结构件（墙、地面、天花板、门框）。
  • 用固定种子把 22 个视频分成 5 个开发、15 个测试、2 个备用，写进 configs/splits.json。
  • 这周找教授在 ScanNet++ 申请表上签字并提交。

做完的标志：给任意一个场景 ID，都能拿到它的 mp4 和去掉结构件后的真值框列表。

容易搞错

CA-1M 自带的 ARKit 位姿、激光深度、注册位姿一律不进流程。流程里用的位姿和深度都是 Pi3X 估出来的，CA-1M 的这些数据只在评测时用来对齐和判断遮挡。

10.5 S4：在 Betty 上跑感知（Mingjian）

感知结果每个场景只在 Betty 上算一次，所有实验组读同一份。这样感知的随机性不会混进组间差异。

大白话

七个施工队比手艺，测量员只派一个，量完的图纸复印七份发下去。谁建得好坏，就只看施工，不看测量。

Betty 上的感知作业：登录节点下权重，计算节点离线跑
  1. 登录节点只做准备。Betty 的规矩是登录节点"编辑、同步、提交，不训练"。在这里把 Pi3X、SAM 3、Boxer 的权重预先下载好。计算节点能不能上网文档没写清，所以按"不能"准备。
  2. 提交作业。用 Slurm 提交到 45 GB 的 MIG 切片或整卡 B200。作业里设离线模式（HF_HUB_OFFLINE=1），只读本地权重。
  3. 算共享的感知结果。20 个场景（5 开发 + 15 测试）各跑一次 Pi3X 和 SAM 3，用作者默认的 25.5 万像素和 32 帧。得到相机、点云和结构类掩码，放进每个场景的 bundle/。
  4. 算两份清单。Boxer 在高清帧（同样 32 帧，换成 1024×768 原图）上找 3D 框；干净对照用 SAM 3 实例掩码加 Pi3X 点云拟合有向框（PCA）。两份都存成清单文件。
  5. 拷回来。结果拷回笔记本，所有组共用。顺手记下每个场景的峰值显存和耗时，后面估 Betty 额度要用。
S4 · 在 Betty 上跑感知

负责 Mingjian 10/14–10/26

  • 开通 Betty 账号；今天在 Hugging Face 申请 SAM 3 和 SAM 3D Objects 的权限。
  • 登录节点预下载权重，计算作业离线跑。
  • 20 个场景各跑一次 Pi3X 和 SAM 3；再跑 Boxer 和干净对照，得到两份清单。
  • 结果拷回笔记本，记下峰值显存和耗时。

做完的标志：20 个场景都有 bundle/ 和两份清单，并有每个场景的显存和耗时记录。

容易搞错
  • MIG 切片不支持 OpenGL 和 Vulkan，所以 Blender 的预览渲染不放 Betty。agent 循环和 Blender 留在笔记本上跑。
  • 笔记本也能跑 Pi3X，但只能到 10 到 15 万像素。正式结果一律用 Betty 上按默认 25.5 万像素算的那份，否则和作者设置对不上。

设计文档第 4、6 节；04 号笔记 §1.2–1.6（登录节点规矩、MIG 不支持图形接口、出网限制）。

10.8 S8：生成和摆放工具（Mingjian）

两个生成工具 gen3d_request 和 place_mesh 先用本地小模型写通，再换成正式的 SAM 3D。11/2 是这一步的闸门。

两个工具从本地开发到正式上线的路线
  1. 本地先写通。笔记本上的 Hunyuan3D-2mini 只要约 6 GB 显存，用它把两个工具的接口写通、调好。它和 Blender、IsaacLab 抢显卡，所以批量生成放在晚上跑。
  2. fal 上核对位姿约定。SAM 3D 会同时给出物体的旋转、平移和尺度，但文档没写清在哪个坐标系。在 fal 上拿 5 个物体试，花费不超过 10 美元。
  3. Betty 部署。SAM 3D 官方要求至少 32 GB 显存，本地 12 GB 跑不了。别人在 A100 上测得进程约 22 GB、约 13 秒一个物体（RecGen 论文），所以放进 45 GB 的 MIG 切片。
  4. 11/2 闸门。装通了，正式实验用 SAM 3D，训练加分项可以做。装不通（HF 审批慢，或 B200 的 sm_100 环境问题），改用本地 Hunyuan3D-2mini 加我们的配准，报告里注明，训练加分项不做。
  5. 校准并跑 P0。在开发集上校准验收门槛（剪影 IoU、Chamfer、尺寸三项，见第 6 章），然后跑 P0，两种清单各一遍。
