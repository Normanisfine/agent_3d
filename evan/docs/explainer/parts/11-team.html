11分工与交接

三个人按流程的三段分工：Yujing 管两头（数据进来、分数出去），Mingjian 管感知和生成工具，Yifan 管中间的 agent。

三个人之间只靠文件交接。文件格式先定下来，各自就能并行开工，不用等别人写完代码。

11.1 三个人各管流程的哪一段

大白话

还是装修。Yujing 是监理，负责交房前的图纸和交房后的验收；Mingjian 是材料商和测量员，备好尺寸和预制件；Yifan 是带施工队的包工头，指挥 agent 把房子搭出来。

Yifan · agent 和驱动
  • 职责：装 AHa-3D 和 Blender 5.2.1；接 Codex 和 Claude 两种驱动，量额度；写 A0–A4 的提示词和路由逻辑；记录每次运行的 token 日志。
  • 主要产出：每次运行的 scene.blend 和 run_log.json；configs/run_caps.json（运行上限）；额度表。
  • 步骤：S1、S2、S7、S9（agent 组）、S10（A4、第二次重复、Claude 复跑；高清帧消融的 agent 运行，按我们的理解）。
  • 要读：AHa-3D 的 AGENTS.md 和 skills、GATOR（细读）、codex exec 和 Claude Code 无头模式的文档、Agentic RSR、LiteReality-Agent、VIGA（清单和链接见第 16 章）。
Mingjian · 感知和生成
  • 职责：申请 SAM 3、SAM 3D 的 HF 权限并在 Betty 上部署；在 Betty 上批量跑 Pi3X、SAM 3、Boxer 和干净对照；本地用 Hunyuan 开发两个生成工具；跑 P0、Hunyuan 小对比、训练加分项。
  • 主要产出：每个场景的 bundle/、inventory.json（Boxer 版）、inventory_clean.json（干净版）；gen3d_request 和 place_mesh，以及它们写进 gen/ 的网格；P0 的结果。
  • 步骤：S4、S8、S9（P0）、S10（高清帧消融的降采样版清单和生成、Hunyuan 小对比、训练）。高清帧消融的 agent 由 Yifan 跑，这是按我们的理解分的，设计文档没写。
  • 要读：π³/Pi3X、SAM 3、Boxer、SAM 3D Objects、φ-RIE、Hunyuan3D-2 仓库 README、PARCC 入门和 fal 接口页；参考 ReScene、RecGen、OVOW、TRELLIS 和 TRELLIS.2（见第 16 章）。
Yujing · 数据和评测
  • 职责：下载 CA-1M 和 VSI；合成输入视频；划分数据集、定阈值；写评测脚本（对齐、匹配、三种结局、漏斗、bootstrap）；拍演示视频；出图；主笔报告。
  • 主要产出：每个场景的 input.mp4 和 gt/boxes.json；splits.json、thresholds.json；评测脚本从 .blend 导出的 export/objects.json；results/ 里的所有表和图。
  • 步骤：S3、S5、S6、S7 和 S9 的打分、S10（演示视频）、S11。
  • 要读：CA-1M、LIVIN（细读）、ARKitScenes、VSI-Bench、BVB、ScanNet++、Scan2CAD、TIDE、Omni3D、SceneActBench、Umeyama 1991（见第 16 章）。

提案三人一起改，由一人代表全组上传，每组只交一份。文档里要写队名 3Heads1GPU 和三个人的名字。

11.2 交接架构图：文件在三人之间怎么流

交接一共四条线。每条线上传的是什么文件、什么时候第一次传，下图逐条点亮。

三人之间的四条交接线
  1. Yujing → 所有人：每个场景的输入视频 input.mp4、splits.json（哪些是开发、测试、备用）、thresholds.json（各项门槛）。两个配置文件 10/20 前提交后不改。
  2. Mingjian → Yifan：每个场景的感知结果 bundle/、物体清单 inventory.json，以及两个生成工具 gen3d_request、place_mesh。A2 起的 agent 组都要用清单，A3 起还要调两个工具。
  3. Yifan → Yujing：每次运行最后的 scene.blend，和记 token、耗时、轮数的 run_log.json。物体框 export/objects.json 由 Yujing 的评测脚本从 .blend 导出。失败的运行也要交，按最后保存的版本打分。
  4. Mingjian → Yujing：bundle/ 里的相机轨迹，评测对齐和判断"看得见"都要用。两份清单 inventory.json、inventory_clean.json 用来判断漏斗第 2 关"检测到"。P0 的场景和它直接写出的 export/objects.json 也直接交给 Yujing，不经过 Yifan。
  5. 提案：三人一起改同一份，由一人代表全组上传。
容易搞错
  • inventory.json 有两个读者。Yifan 拿它当 agent 的待建清单；Yujing 拿它算"检测到"这一关。两边读的必须是同一份文件，否则漏斗第 2 关和 agent 实际看到的清单对不上。
  • A0、A1 不读清单，漏斗里没有"检测到"这一关，评测时直接从"看得见"跳到"建出来"。

11.3 文件约定

设计文档第 15b 节定了一套文件约定，各章和三人交接都按它来。下图是目录结构，表格写清每个文件谁写、谁读、装什么。

文件谁写谁读内容和格式要点
scenes/<scene_id>/input.mp4Yujing（S3）Mingjian、YifanCA-1M 的 1024×768 帧按 10 fps 合成，一个连续镜头（AHa-3D 的要求）
scenes/<scene_id>/gt/boxes.jsonYujing（S3）只有评测去掉结构件后的真值框。相机轨迹、激光深度也一样只给评测，不进流程
configs/splits.jsonYujing（S3、S6）所有人22 个视频 ID 分成开发 5、测试 15、备用 2，写明种子；10/20 前提交后不改
configs/thresholds.jsonYujing（S6，三人确认）所有人判据 I（IoU3D ≥ 0.25，另报 0.5）、判据 D（d̂ ≤ 0.5 且最长边之比 0.67–1.5）、宽松门槛、"看得见"门槛；10/20 前定死
configs/run_caps.jsonYifanYifan每次运行的墙钟和轮数上限，取 A1 在 3 个开发场景上中位数的 2 倍；10/26 前提交，所有组共用
perception/<scene_id>/bundle/Mingjian（S4）Yifan、YujingAHa-3D 的 bundle 格式：Pi3X 的相机和点图（32 帧、25.5 万像素）、SAM 3 结构类掩码；每个场景只在 Betty 上算一次。Yujing 用里面的相机轨迹做对齐
perception/<scene_id>/inventory.jsonMingjian（S4）Yifan（A2–A4 的待建清单）、Yujing（漏斗第 2 关）Boxer 清单，每项一个 3D 框加 2D 裁剪图；agent 组只用这一份
perception/<scene_id>/inventory_clean.jsonMingjian（S4）Yujing干净对照清单（SAM 3 实例掩码加 Pi3X 点云拟合的有向框），只用于"检测到"这一关和 P0
gen/<scene_id>/<object_id>/c<k>/mesh.glbMingjian 的工具（S8）agent、Yujing生成的网格；同一目录下的 placement.json 是 place_mesh 返回的 PlacementResult（状态、位姿、拟合分数、花费）。生成结果按"帧、掩码、后端、种子"缓存，接口照抄 02 号笔记 §7.2
runs/<arm>/<scene_id>/<seed>/scene.blendYifan（P0 由 Mingjian）Yujing每次运行最终保存的场景；撞上限或跑崩也交最后一版
runs/…/run_log.jsonYifan（P0 由 Mingjian）Yujing（成本轴）token 数（输入、缓存、输出）、按 API 价折算的美元、墙钟时间、轮数、失败原因、fal 费用
runs/…/export/objects.jsonYujing 的评测脚本（P0 直接写）评测用 AHa-3D 的 export_model.py 从 .blend 导出，每个语义根节点（按 instance_id 分组）一个世界坐标有向框
results/Yujing所有人分档表、漏斗图、成本-精度图、bootstrap 结果
容易搞错
  • 路径以设计文档第 15b 节为准。代码结构和这套约定之外的配置、日志细节，第 16 节留给执行时定。
  • 真正要守住的是内容约定：export/objects.json 用世界坐标，run_log.json 分开记输入、缓存、输出三种 token。否则 Yujing 那边对齐和算成本都会出错。
  • agent 组只读 inventory.json，不读 inventory_clean.json。干净版只在评测"检测到"这一关和 P0 里用。
