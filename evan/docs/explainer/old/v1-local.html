小物体去哪了

用手机拍一段房间视频，让大模型 agent 把它搭成一个 Blender 场景。家具大多能搭出来，杯子、瓶子、书、遥控器这些小东西却常常没了。这个项目要量清楚它们丢了多少、丢在哪一步，以及怎么补最划算。

  • Q1以 AHa-3D 为代表的"视频转 3D 的 agent"，按物体大小分档，各丢了多少物体？
  • Q2每个丢掉的物体，是卡在哪一关：画面里根本看不清、没被找到、没被建出来，还是建歪了？
  • Q3流程的其他部分全部固定，只换小物体的处理方式，哪几种做法在成本和精度上最划算？

01

这个项目在做什么，为什么值得做

起点是 AHa-3D。它是一个开源的 agent 系统：输入一段房间视频，大模型（作者用的是 GPT-6 Astra）一边看视频截图、一边写 Blender 脚本，把墙、家具、柜门一件件搭出来，再自己对比、修改。成品可以直接拿去做机器人仿真。

它有两个空白，正好是我们的机会。

  • 没有任何定量结果。博客里只有几段对比视频，没有一个"搭得准不准"的数字。
  • 小物体是有意做粗的。作者博客里演示用的任务描述写的是 "approximate small objects"（这是一次对比实验的任务，不一定是发布版的默认提示词）。小物体从一个 108 项的资产库里挑，里面没有杯子、书、显示器。作者试过用 3D 生成模型（SAM 3D、TRELLIS.2）补小物体，做完又搁置了，没写原因。

"小物体交给 3D 生成模型"这个点子本身已经有人做了：GRASE、LIVIN、GATOR、LiteReality-Agent、CoDimRecon 都用到了（第 14 部分有对照表）。所以我们不把"用生成模型"当成自己的方法贡献。我们的贡献是把账算清楚：

  • 第一次按物体大小分档，给出这类系统的召回和摆放精度；
  • 把每个丢掉的物体归到具体是哪一关丢的（第 5 部分的"漏斗"）；
  • 在同一套流程、同一份感知结果下，公平比较几种小物体处理方式，同时报花了多少钱。

还有一个让问题更有意思的事实。GATOR 给 GPT-6 每个物体 10 分钟从零写代码建模：在 ScanNet++ 上，几何误差（Chamfer 距离 0.033）只比"先生成再精修"（0.031）差一点；但在桌面小物体上是 0.016 对 0.009，差了将近一倍。整间房、固定预算下，生成到底划不划算，没人知道。所以"生成模型一定更好"不是前提，而是要检验的问题，哪种结果出来都算发现。

我们不做的事：不训练主线模型（训练只是加分项，见第 13 部分）；不量化形状和外观好不好看（只做定性展示）；不做动态物体、人体、室外；不重新实现 GRASE 或 GATOR 的整套系统，只借它们的做法。

算失败的情况（即使代码都跑通了）：

  • 实验组之间的差距还没有同一组跑两次的差距大，却写成了"某组更好"；
  • 拿被评测的物体来做对齐，把要测的误差抵消掉了；
  • 看了测试集结果再回头调阈值或提示词；
  • 把 Boxer 在 CA-1M 上的好成绩当成泛化能力来报。它训练时见过 CA-1M。
02

前置知识：先懂这九件事

每张卡片先用一两句话讲清楚是什么，再说明它在项目里用在哪。公式和细节放在"深入"里，第一遍可以跳过。

相机：内参和位姿

一张照片要变成 3D，得先知道两件事。内参描述镜头本身：焦距多长、画面中心在哪。位姿（也叫外参）描述拍这张照片时，相机站在房间的哪个位置、朝哪个方向。

深入：针孔模型

空间里一点 X（世界坐标）投到像素 (u, v)：

[u, v, 1]ᵀ ∝ K · (R·X + t) K = [[f, 0, cx], [0, f, cy], [0, 0, 1]]

K 是内参，(R, t) 是位姿。AHa-3D 存的是相机到世界的 4×4 矩阵（c2w），Z 轴朝上。

用在：Pi3X 从视频里同时估出每帧的内参和位姿；评测时拿它和 CA-1M 的真实相机轨迹对齐。

深度、点云和"米制"

知道每个像素离相机多远（深度），再结合相机参数，就能把像素"反投影"成 3D 点，所有点合起来就是点云。米制的意思是单位真的是米。只靠单目视频估出来的尺度往往有偏差，所以叫"近似米制"。

深入：尺度误差为什么危险

整体尺度差 10%，离对齐中心 3 米远的物体就会被挪开约 30 厘米。小物体的匹配门槛只有几厘米到十几厘米，所以尺度误差会直接把一个形状完美的杯子判成"建歪了"。这就是评测里要同时报"修正尺度"和"不修正尺度"两个版本的原因。

用在：Pi3X 输出的点云是 agent 量尺寸的依据，也是 SAM 3D 生成时摆位置的依据。

分割和掩码

分割就是在图上把某个物体的像素圈出来。圈出来的结果叫掩码：一张黑白图，白色是物体。SAM 3 可以按文字提示（比如"cup"）分割，也能分出同一类里的不同个体。

用在：AHa-3D 默认只分割人、玻璃、镜子、地面、墙；我们的干净对照用 SAM 3 分出每个物体，再配合点云拟合出 3D 框。生成模型也要靠掩码知道"生成哪个东西"。

3D 框（有向包围盒）

用一个长方体把物体框住，描述它的中心位置（3 个数）、长宽高（3 个数）和朝向。家具一般只绕竖直轴转（1 个数，叫 yaw），所以常说 7 自由度；朝向允许任意转动时是 9 自由度。

深入：CA-1M 的框长什么样

每个框有位置、尺寸、3×3 旋转矩阵和 8 个角点，坐标系 Z 朝上。抽查 1,173 个框，只有 24 个带俯仰或侧倾，其余都只绕竖直轴转。

用在：真值就是 3D 框；我们从 Blender 场景里也导出每个物体的 3D 框，两边比。

图生 3D（生成模型）

给一张物体的图（加掩码），生成模型直接"猜"出完整的 3D 网格，包括看不见的背面。大多数模型（比如 Hunyuan3D、TRELLIS）只输出一个摆在标准姿势、缩放到单位大小的网格（叫"规范空间"），它在房间里的位置、朝向和尺寸还得另外求。

深入：SAM 3D 为什么特别

SAM 3D Objects 生成时会直接给出相机坐标下的旋转、平移和尺度，还能接收点图，并且专门训练过遮挡和小物体。代价是显存大：官方要求至少 32 GB，A100 上约 13 秒一个物体。注意它发布的代码把尺度取三个轴的平均（各向同性），细长物体可能还要我们再调一次尺寸。

用在：A3、A4、P0 三类实验组用它补小物体。

配准：ICP 和剪影匹配

配准就是把一个模型挪到和观测对上的位置。ICP 反复找"模型上离观测点最近的点"，再算一个让它们整体最贴近的平移和旋转。剪影匹配把模型投到几张截图上，看投影出的轮廓和真实掩码重合了多少，再小步试探着调位置、朝向、尺寸。

深入：GRASE 的剪影搜索

目标函数是各视角的 (1 − 掩码 IoU)，加边界距离、最差视角和点到面距离几项；不求导，用有界坐标搜索：3 层，每层 4 遍，步长 1、0.5、0.25。可调范围：位置约 ±0.18 × 最长边，yaw ±0.45 弧度，尺寸 0.75 到 1.25 倍。

用在：place_mesh 工具先用生成模型给的位姿或 3D 框当起点，再做 ICP 和剪影搜索。

agent、harness 和驱动模型

agent 是会自己调用工具的大模型：它能运行命令、看图、写代码，根据结果决定下一步。harness 是包在外面的那一套：工具、规则、检查步骤、什么时候算完成。驱动模型是 agent 背后用的那个大模型。

深入：驱动模型会影响多少

Agentic RSR 的新版论文在同一个 harness、18 个 Blender 场景上比较驱动模型：Claude Opus 5.5 18/18 通过，GPT-6 Astra 和 Sonnet 5.5 各 15/18，GPT-6.1 Sol 12/18。驱动不同，结果差得很多，所以我们全程固定驱动，换驱动只作为单独的复跑实验。

用在：AHa-3D 就是一个 harness。主实验的驱动是 Codex CLI 上的 GPT-6，开发调试用 Claude Code 上的 Opus 5.5。

Blender 和 bpy

Blender 是免费的 3D 软件。bpy 是它的 Python 接口：不用点鼠标，写脚本就能建物体、摆位置、渲染。AHa-3D 让 agent 写的就是 bpy 脚本，所以场景完全可编辑，每个物体都是独立的对象。

import bpy
bpy.ops.mesh.primitive_cube_add(size=1, location=(1.2, 0.4, 0.75))
cup = bpy.context.object
cup.scale = (0.08, 0.08, 0.10)   # 长宽高，单位米

用在：AHa-3D 要求 Blender 5.2.1 版本，因为它的资产库是用这个版本保存的。

评测里的四个词

IoU：两个框重叠体积除以合起来的总体积，1 是完全重合。匈牙利匹配：一对一配对预测和真值，让总误差最小。bootstrap：对场景反复有放回地抽样、重算指标，看结果会波动多少，得出置信区间。帕累托前沿：在"花钱"和"精度"两个维度上都没有被别的方法同时打败的那些方法。

用在：第 8 部分的评测全用这几个工具。

03

AHa-3D 是怎么工作的

整条流程分五段。前一段由工具自动完成，后四段由 agent 主导：它看截图、调工具、写脚本，直到审查员点头。

几个会影响我们的细节

  • Pi3X 只看 32 帧（可选 64 帧），从整段视频里均匀抽，每帧缩到 25.5 万像素以内，大约 574×434。小物体在这个分辨率下可能只剩十几二十个像素，第 5 部分有计算器。
  • 检查工具的门槛没有校准过。轮廓重合度低于 0.65 或边界偏差超过 12 像素就提醒 agent，代码注释原话是 "triage heuristics, not calibrated"。
  • 物理检查：穿进别的物体超过 5 毫米算碰撞；底下 2 厘米内没有支撑面算悬空；再用 Blender 刚体模拟 2 秒，看会不会倒。
  • 审查员写死成 codex exec --image。用 Codex 驱动时直接能用；用 Claude 驱动时要加一个转发 shim，之前的会话里做过。
  • 只能在 Linux 上跑，Blender 必须是 5.2.1，输入必须是一个连续镜头，作者只在 96 GB 显存的机器上验证过。
  • 成本：按 API 价折算，作者 10 秒的 office48 视频跑一次约 12 到 22 美元。我们用订阅跑，账单不按次算，所以要自己记 token 再折算。
04

我们怎么改：七个实验组

我们把流程归成四个环节：找物体 → 建形状 → 摆准 → 检查。每个实验组只在其中一两个环节上动手，其余全部保持一致，包括同一份感知结果（每个场景只算一次）、同一个驱动模型、同一个 AHa-3D 版本。这样两组之间的差别，就只能归因于改动的那一环。

组在前一组基础上改什么回答什么问题场景数
P0不用大模型。Boxer 框出所有物体，每个框用 SAM 3D 生成并自动放进场景；过不了验收的，就用框本身当方块。小物体到底需不需要 agent？15
A0AHa-3D 原样运行，用作者的提示词。原版丢了多少？15（额度不够时缩到 5）
A1提示词明确要求逐个建出所有看得见的小物体，只用代码和方块。公平的基线：认真做，但不加任何工具。15
A2加一份物体清单：Boxer 在高清帧上检测，得到 3D 框和裁剪图，agent 要逐项处理，或说明为什么跳过。漏掉是因为没找到吗？15
A3r加生成：清单里估计最长边小于 0.5 米的物体，调用 SAM 3D 生成并摆放，过验收才保留，否则退回方块。按尺寸规则生成有用吗？15
A3v和 A3r 相同，只是由 agent 逐个决定生成还是写代码（它能看裁剪图和测量值）。让 agent 自己判断，比规则好吗？15
A4在 A3v 之后，agent 对每个生成物体再做"改、渲染、看"的精修，每个最多 3 轮。GATOR 的做法。精修值不值这份钱？5（加分项）

另外几项小实验

  • BVB 重新打分：BVB 项目公开了别人跑出来的 .blend 结果，拿我们的评测脚本重新打分，当免费的额外基线。它们的坐标系和我们不同，对不齐就不报。
  • 高清帧消融：A3v 改用 Pi3X 降采样后的帧做清单和生成，跑 5 个场景，量出"用高清帧"单独贡献了多少。
  • Hunyuan 小对比：用固定种子抽约 50 个小物体，比较"SAM 3D 自带的位姿"和"Hunyuan3D-2 只生成形状、再用我们的工具配准"，看谁摆得准。这是物体级实验，不进 agent 循环。
  • 第二次重复：A1 和 A3v 在 5 个场景上各多跑一次，用来估计同一组跑两次会差多少。
  • Claude 复跑：用 Claude Opus 5.5 当驱动，在 5 个场景上重跑，证明结论不是某个驱动模型特有的。额度够就跑全部 5 个主实验组，不够只跑 A1 和 A3v。

每次运行的规则

  • 所有组用同一个墙钟时间上限和同一个轮数上限。具体数值在第 1 周量完 office48 后定，初值取 A1 在开发集上中位数的 2 倍。
  • 跑崩了或撞了上限，重跑一次；还不行就拿最后保存的 .blend 照常打分，记为失败。各组的失败率单独报，不剔除失败的运行。

订阅额度不够时，按这个顺序砍：

  1. A0 缩到 5 个场景
  2. Claude 复跑只留 A1 和 A3v
  3. 第二次重复缩到 3 个场景
  4. 取消 A4
  5. 测试场景从 15 个减到 10 个
  6. 去掉 A3r

原则是不换驱动模型：换了就和作者的设置不可比了。

05

漏斗：每个小物体丢在哪一关

对每一个真值物体，我们记录它最远走到了哪一关。每一关都会筛掉一部分物体，画出来就像一个漏斗。这张图是报告的主图：每个实验组、每个尺寸档各一根堆叠条形。

小物体在画面里占几个像素

第 ① 关为什么重要，用这个计算器一试就明白。改物体大小和距离，看它在不同分辨率下能占多少像素。

画面宽 × 高物体跨度约占面积判定

按针孔模型估算：跨度 = 焦距像素 × 大小 ÷ 距离；面积按正对相机的方块近似。视角 60° 是 iPad 主摄的量级，属于估计值。"看得见"的门槛是 100 像素面积；生成工具在掩码小于约 200 像素时会直接返回 too_small。

默认值下，10 厘米的杯子在 2 米外，在 AHa-3D 用的分辨率里只跨二十来个像素，换成 CA-1M 原帧能多出将近一倍。这就是 A2、A3 坚持在高清帧上找物体和裁剪的原因。如果漏斗显示大部分小物体卡在第 ① 关，那么最便宜的改进也许根本不在 agent 身上。

两个我们自己写的工具

生成和摆放拆成两个工具：这样 agent 可以只重新摆放（比如换一个支撑面），不用重新生成；生成还可以异步批量提交，agent 同时去搭别的东西。

gen3d_request(object_ids, backend="sam3d", n_candidates=2, frames="auto")
  → 挑最清楚的帧，裁出物体，调用生成模型，清理网格（Z 朝上、单位米）
  → 最好那一帧的掩码不到约 200 像素：直接返回 too_small

place_mesh(object_id, candidate_id, init="backend_pose" 或 "obb")
  → 起点：SAM 3D 给的位姿，或者 3D 框
  → ICP 贴到点云上 → 多视角剪影搜索 → 验收
  → 返回 status：accepted / rejected_fit / too_small / backend_error / timeout
深入：验收条件（必须比方块好才保留）
  • 多帧平均剪影 IoU ≥ max(0.6, 同一物体方块版的 IoU + 0.03)
  • 观测点到网格的平均距离 ≤ max(1.5 厘米, 0.1 × 最长边)
  • 尺寸在 3D 框的 0.75 到 1.25 倍之间
  • 穿进支撑面不超过 1 厘米

这些是初值，第 1 周用 10 个开发集物体校准。另一个 Blender agent（VIGA）加了 SAM 3D 之后图像指标反而下降，所以这道验收是必须的。

评测：怎么判定"建好了"

评测分五步：把重建结果对齐到真值 → 按大小分档 → 一对一配对 → 判定每个真值物体的结局 → 统计。

1. 对齐：只用相机轨迹

Pi3X 的坐标系和真值的坐标系不一样，要先对齐。我们只用相机轨迹来对齐：把 Pi3X 估出的每帧相机位置和 CA-1M 的真实相机位置对应起来，求一个整体的平移、旋转和缩放。绝不用被评测的物体来对齐，否则对齐这一步会把我们要测的误差悄悄吸收掉。

同时报两个版本：允许修正尺度（Sim(3)）和不修正尺度（尺度固定为 1）。后者能看出 Pi3X 自己的尺度误差有多大。

深入：Umeyama 对齐

给定对应的相机中心 pᵢ（Pi3X）和 qᵢ（真值），求 s、R、t 使下式最小：

Σᵢ ‖ qᵢ − (s·R·pᵢ + t) ‖²

Umeyama 算法有闭式解（SVD）。加重力约束时，R 只允许绕竖直轴转。VSI 开发集和 BVB 结果没有相机轨迹，只能退而用 L 档家具加地面来对齐，并且只给 XS、S、M 三档打分，表里会注明。

2. 按大小分档

按真值框的最长边分四档，每档都报真值物体的数量：

档最长边典型物体
XS< 0.2 m杯子、鼠标、遥控器、手机
S0.2 – 0.5 m书、台灯、键盘、花盆
M0.5 – 1.5 m椅子、床头柜、显示器、电视、小书架
L≥ 1.5 m沙发、床、餐桌、大柜子

3. 一对一配对

用匈牙利算法把预测物体和真值物体一对一配起来，不看类别。配对时的"距离"是按物体大小归一化后的中心距离：同样偏 10 厘米，对杯子是大错，对沙发不算什么。

4. 每个真值物体的三种结局

结局条件
建好了通过严格判据。有两套严格判据，分开各报一张表：I = 3D IoU ≥ 0.25（方便和前人比较）；D = 归一化中心距离 ≤ 0.5，且最长边之比在 0.67 到 1.5 之间（对小物体更稳）。
建坏了没过严格判据，但在宽松门槛内：归一化中心距离 ≤ 1.0，或 3D IoU ≥ 0.1。
漏了连宽松门槛都没进。
深入：归一化中心距离和 3D IoU d̂ = ‖ c_pred − c_gt ‖ / r_gt r_gt = 真值框半对角线长 IoU3D = 交集体积 / (预测体积 + 真值体积 − 交集体积)

为什么不只用 IoU：小物体的 3D IoU 对一点点偏移极其敏感，一个 8 厘米的杯子偏 3 厘米，IoU 就掉得很厉害。归一化中心距离对大小物体一视同仁。两套都报，读者可以自己对照。

精确率（建出来却匹配不上任何真值的物体）作为次要指标报。CA-1M 是穷举标注，这个数有意义。所有阈值都是初值，在开发集上看一遍分布后，10/20 前写进 configs/thresholds.json，之后不再改。

5. 统计和成本

  • 配对比较：同一个真值物体在不同组里的结局两两对照，而不是只比总数。
  • 置信区间：按场景做 bootstrap，给出 95% 区间。
  • 噪声底线：A1 和 A3v 的第二次重复告诉我们同一组跑两次差多少。组间差距比这个小的，不下结论。
  • 成本：每次运行记录 token 数（输入、缓存、输出）、墙钟时间、生成费用，token 按官方 API 价格折算成"API 等价美元"。
  • 结论的写法：画出"成本-精度"的帕累托前沿，说哪几种做法最划算，而不是简单地说哪种最好。

标出某个物体所占像素的黑白图。
3D 框（OBB）
包住物体的有向长方体：中心、长宽高、朝向。
规范空间
生成模型输出网格时用的标准姿势和单位大小，和房间里的真实位置无关。
ICP
迭代最近点，把模型挪到贴合点云的位置的经典算法。
剪影
模型投到图上的轮廓，用来和真实掩码比重合度。
agent / harness
会自己调用工具的大模型 / 包在它外面的工具和规则。
驱动模型
agent 背后实际干活的大模型，比如 GPT-6 或 Claude Opus 5.5。
bpy
Blender 的 Python 接口。
IoU3D
两个 3D 框重叠体积占合并体积的比例。
匈牙利匹配
让总误差最小的一对一配对方法。
Sim(3) / Umeyama
带缩放的整体平移旋转 / 求它的闭式算法。
bootstrap
反复有放回地抽样重算，估计结果的波动范围。
帕累托前沿
在成本和精度上没被别人同时打败的那些方法。
同源 / 污染
被测模型训练时见过测试数据的来源，成绩会偏高。
消融
只去掉或换掉一个部件，看结果变多少，以此判断这个部件的贡献。
召回 / 精确率
真值物体里被建好的比例 / 建出来的物体里对得上真值的比例。
