# 清单 v2 整理成核对表：开发集上的阈值扫描（5 个场景：47331262 45261575 47115469 47331319 42899698）

核对表（`smallobj.checklist.build`）只按几何整理清单 v2，不看真值、不用 VLM：同类别的重复去掉，不同类别叠在一起的并成一组（代表 = 分数最高的，其余类别列为备选），落在更大的框里面的不去掉；可选的尺寸上限只留最长边小于它的条目。"重叠" = 3D IoU > 阈值，或大小相当（最长边之比 ≤ 3）且中心距离 < 比例 × 两个框里较短的对角线。

判据 D、宽松门槛、Sim(3) 对齐，同 `inventory_v2_dev.md`。每格是"检测到 / 建对"占真值的比例：

- **配上**：只拿各组的代表和真值一对一配对（`score_inventory` 的配法），配上真值的代表占核对项的比例。
- **建对**：同一次配对里，代表过了严格判据 D 的真值占比。
- **检测到**：拿组和真值一对一配对，组里任一成员过宽松门槛就算这组能配这个真值，代价取成员里最小的；配上的真值占比。一组最多算一个真值；每组只有一个成员时（前两行）和代表配对是同一回事。

"每间房"是 5 间房核对项数的 最少 / 中位 / 最多。标"网格外"的几行是原定网格之外加的（中心比例 0.2）。

## 选定：IoU 0.4、中心 0.2、不设上限

原定网格里没有一格能把 XS、S 的"检测到 / 建对"都守在 v2 原样的 2 个点上下：XS 检测到最好的一格也掉 4.6 个点；IoU 阈值在中心比例 0.35、0.5 下几乎不起作用（条目数只差几条到几十条），起作用的是中心距离那一条。所以在网格外加了中心比例 0.2，选 **IoU 0.4、中心 0.2、不设上限**：核对项 2295 → 1666（少 27%），XS 81% / 58% → 79% / 56%，S 79% / 51% → 79% / 49%，四个数都在 2 个点上下（S 建对差 2.1 个点，最多）。M、L 的代价：M 74% / 49% → 72% / 48%，L 56% / 26% → 56% / 22%。尺寸上限不设：1.5 m 只再少 11 条，L 建对却掉到 13%；0.5 m 再少 17%，但 S 检测到再掉 2.1 个点，M 只剩 44% / 8%、L 全没了，大家具要留给 agent 的话，写提示词时按 size 筛就行，不必在核对表里丢掉。更看重条目数的话，网格内可以退到 IoU 0.25、中心 0.35、不设上限：1387 条（少 40%），XS 76% / 55%、S 78% / 48%。
