## 看到的方向（3 个场景，不是结论）

1. **A0 几乎全漏小物体。** XS 138 个一个都没建出来，S 只建对 1%。M、L 能建对两成多。
2. **只要在提示词里加上小物体策略，小物体就好很多。** 按场景平均，A1 的 XS 从 0 到 .14，S 从 .05 到 .35，M、L 也更高（.22 → .30、.22 → .38）。
3. **A2（给 agent 一份清单）和 A1 差不多，略好一点。** 清单在 XS 上只检测到 138 个里的 10 个（7%），检测这一步就是 XS 的瓶颈。
4. **A3（图生 3D）没有比 A1、A2 好。**
   - 6 次 A3 运行共生成 160 次，`place_mesh` 接受了 10 个，最后场景里只留下 5 个：A3r 42897538 的电话和两个靠垫，A3v 42897538 的格子靠垫，A3v 42898849 的柴火炉。其余都是 agent 用代码搭的。
   - 被拒的原因主要是生成的网格多半是扁片，尺寸比或剪影对不上（同开发集，`../phase2_dev.md` 发现 2）。
   - 所以 A3 的数字其实反映的是"提示词里多了生成这一步"的 A1/A2，不是生成网格本身的效果。
5. **"建了但没摆准"不少。** A1 到 A3 在 S 档建了没摆准的比例在 .18–.20，比建对的 .14–.17 还多。
6. **驱动和规则的影响。** 旧 Codex A1 用的是旧规则（每次最多 64 分钟、修约 3 次就停）。在同样这 3 个场景上，它按场景平均是 XS .07 / S .23 / M .25 / L .35。Opus A1 用原版规则是 .14 / .35 / .30 / .38，四档都更好。不过驱动和规则是一起换的，分不开是哪个起的作用。

## 文件

- `runs.md`：每次运行的用时、token、额度、对齐残差和四档召回。
- `summary.json`：上面所有数字，包括建了没摆准和漏掉的比例。
- `funnel.png`：看得见 → 检测到 → 建出来 → 建对了。图上的黑线是流程分辨率下看得见的比例。
- `recall_by_bin.png`：判据 I 和 D、修尺度和不修尺度的四档召回。
- `funnel_pre_g1.png`、`sensitivity.md`：对照用，G1 冻结之前的口径，加上随机挪开 0.5–1.5 m 的碰巧基线。
